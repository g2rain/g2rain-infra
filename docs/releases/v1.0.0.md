# v1.0.0 · g2rain-infra 首个稳定版

G2rain（谷雨）是面向企业的开源智能体平台，连接模型、知识与业务工具，以 SaaS 基座和应用开发工具链支撑智能应用落地。`g2rain-infra` 是其中的基础元数据与分布式发号服务，不是整个平台、Gateway、IAM 或前端应用的替代品。它交付公共字典、Locale 与国际化消息，以及 Redis Worker 租约 Snowflake 和 MySQL 号段两类 ID 分配能力；接口调用仍需要由 Gateway、IAM、数据库、Redis、Nacos 和部署环境共同提供安全与运行保障。

## 交付、构建与镜像

- 项目版本：`1.0.0`；许可证：根目录 Apache License 2.0（`Copyright © 2025 g2rain.com`）。
- 构建要求：JDK 25、Maven 3.9+；运行要求：MySQL 8.0.13+、Redis、Nacos，以及与环境一致的 IAM/Gateway 与消息消费配置。
- 镜像：`ghcr.io/g2rain/g2rain-infra:1.0.0` 和 `ghcr.io/g2rain/g2rain-infra:sha-<完整提交SHA>`；不更新 `latest`。
- 镜像使用 Eclipse Temurin Java 25 JRE，Jib 从 Spring Boot 可执行 Jar 组装，入口为 `com.g2rain.infra.Application`，声明端口 `8080`；OCI source、title、version 与 `Apache-2.0` 标签指向本仓库。
- 本地验证和本地镜像：`mvn clean verify` 后运行 `./build.sh 1.0.0`。脚本会再次执行 Maven `clean install`（含现有测试），再以同一 Jib 配置构建到本地 Docker daemon。GitHub Actions 在 tag 提交上同样先执行完整 Maven 构建，再以该脚本直接推送 Jib 镜像。

## 发布顺序与 GHCR

1. 按 `feature/* → develop → main` 流程，将发布改动与本说明合入 `main`，并在该提交完成验证。
2. 在该 main 提交创建并推送 `v1.0.0`。工作流只接受精确的 `v<major>.<minor>.<patch>` 格式，会验证 tag 提交在 `main` 历史且本文件非空。
3. 成功后确认 Actions 摘要同时列出版本标签与完整 SHA 标签；登录成功、构建成功或部分 layer 上传都不代表标签已成功推送。
4. 首次成功推送后，在 GitHub 仓库 **Packages → g2rain-infra → Package settings → Change visibility → Public** 将包设为 Public，输入包名确认。此设置会持续应用于同一包的后续版本；若组织管理员禁用修改，请联系组织管理员处理。
5. 已有包即使工作流声明 `packages: write`，仍可能需要在 **Package settings → Actions access** 授予 `g2rain/g2rain-infra` 写权限；遇到 GHCR `denied` 应先检查此项与组织 Packages 策略。

公开后可匿名拉取指定版本：`docker pull ghcr.io/g2rain/g2rain-infra:1.0.0`。私有包需要使用具备 `read:packages` 权限的凭据登录。镜像发布本身不创建 GitHub Release、不部署服务，也不执行数据库迁移。

## 配置、安全与已知限制

运行时通过环境变量、Secret 或受控 Nacos 配置注入数据库、Redis 和 Nacos 凭据；不要通过镜像、命令行或仓库提交传递生产密钥。Jib 最终镜像不包含仓库源文件、SQL、`codegen.properties` 或 Docker 构建上下文；但 Spring Boot Jar 会包含 `application.yml` 与 `application-dev.yml`。目前它们仍含开发默认凭据，构成公开镜像与版本库泄露风险，必须在首次公开推送前由维护者迁移/覆盖并在曾复用时轮换，不能把 Docker 忽略规则当作处理手段。

本仓库没有 `src/test` 测试源码，因此 `mvn clean verify` 只验证编译、打包和 Maven 生命周期，不能证明 Redis 租约、时钟回拨、号段并发、MySQL 约束、事件一致性、授权或真实部署。在线演示、容器构建、GHCR 推送、匿名拉取和部署验收是彼此独立的验证项；本发布准备未声称它们已完成。其余架构接入与安全限制见[架构差异与接入项](../architecture/deviations.md)。
